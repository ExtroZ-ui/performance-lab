# Метрики производительности

Два HTTP-метода имитируют блокирующий ввод-вывод ожиданием 400 мс. `/work/platform` использует пул из 24 обычных потоков, `/work/virtual` запускает виртуальный поток на задачу. Оба обработчика возвращают `CompletableFuture`. Поле `virtual` в ответе показывает, на каком потоке выполнялась задача.

## Повтор замеров

Нужны JDK 21+, Maven, Python 3.9+, JMeter 5.6.3, Prometheus и Grafana. В PowerShell из корня проекта выполните команды, подставив пути к распакованным инструментам.

```powershell
mvn package
py .\run_lab.py --prometheus 'C:\tools\prometheus\prometheus.exe' --grafana-home 'C:\tools\grafana' --jmeter-home 'C:\tools\apache-jmeter-5.6.3' --run-dir .\repeat --keep-open
```

Скрипт запускает локальные сервисы, проверяет сбор метрик, проводит два прогона JMeter и сохраняет ответы Actuator и результаты Prometheus. Укажите новую папку для каждого прогона. После замеров скрипт выведет ссылку на Grafana с диапазоном времени теста. Нажмите Enter, чтобы остановить локальные сервисы.

## Файлы

- `src` содержит приложение и параметры эксперимента.
- `load/throughput.jmx` содержит общий сценарий JMeter. Тип потоков задаёт свойство `mode`.
- `monitoring` содержит конфигурацию Prometheus и дашборд Grafana.
- `evidence/measurements.json` содержит показания `COUNT` до и после 10-секундных интервалов, замеры JMeter и время прогона.
- `evidence/*.jtl` содержит исходные замеры JMeter. `evidence/grafana-*.png` содержит скриншоты Grafana.

JMeter поддерживает 96 параллельных клиентов с постепенным запуском в течение 4 секунд. На каждый режим отведено 42 секунды нагрузки. Actuator опрашивается после разогрева и повторно через 10 секунд. В фильтре `tag=uri:/work/platform` или `tag=uri:/work/virtual` учитываются завершённые запросы только к выбранному обработчику.
